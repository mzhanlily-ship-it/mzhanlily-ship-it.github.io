Understanding customer ordering with SQL

Do recorded ordering frequency and spending differ across customer income groups?

I contributed code for the first analysis question and helped coordinate the group. Database design and the broader report were team outputs; this case focuses on the customer-analysis module.

Start with the denominator

“Orders per customer” can mean orders divided by all registered customers, or by customers who actually ordered. These are different measures. The report query uses a LEFT JOIN to retain customers with zero orders and COUNT(order_key) to count actual orders.

The relevant relationship is dim_customer.customer_key → fact_order.customer_key. A customer can have many orders. Customer keys must be unique, and adding another one-to-many table could inflate the order count.

-- Reformatted frequency query from the team report, Appendix D.
-- Denominator: registered customers, including those with no orders.
SELECT c.income_group,
       COUNT(DISTINCT c.customer_key) AS customer_count,
       COUNT(f.order_key) AS total_orders,
       ROUND(COUNT(f.order_key) * 1.0 /
             COUNT(DISTINCT c.customer_key), 2) AS avg_orders_per_customer
FROM dim_customer AS c
LEFT JOIN fact_order AS f ON c.customer_key = f.customer_key
GROUP BY c.income_group, c.income_group_order
ORDER BY c.income_group_order;

Interpret the evidence, without overclaiming

Recorded order frequency varies by only 0.02 orders per registered customer across these groups. Spending averages vary more, but this table alone cannot establish why: order size, prices, customer mix and outliers may all contribute.

I would not use income alone to choose a targeting strategy from this evidence. A next analysis would separate active-customer frequency, average order value and the distribution of spending, while checking group sizes and the observation window.

What was checked for this portfolio?

A small synthetic SQLite fixture tests three registered customers, two active customers and three orders. The query returns 1.0 orders per registered customer; an active-only denominator returns 1.5. It also demonstrates why COUNT(*) after the LEFT JOIN would be wrong.

This test checks query behaviour only. The supplied original database could not be read successfully, so the original totals, currency conversion and data quality have not been independently revalidated. No customer records are published.
